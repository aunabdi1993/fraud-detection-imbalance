# Chapter 3: Methodology

## 3.1 Dataset
Source: ULB European credit-card fraud (Kaggle). See Table 1
(dissertation/tables/table_dataset.csv), generated by src/data_loader.py.

Validated against published benchmarks: 284,807 transactions, 492 fraud
(0.1727%), imbalance ratio 1:578, zero missing values, 48-hour window.
The file SHA256 is recorded in data/processed/manifest.json so every
reported result is traceable to an exact copy of the data.

### 3.1.1 Duplicate records
1,081 rows are exact duplicates across all 31 columns. However, 9,144 rows are
duplicates once Time is excluded — and Time is dropped as a feature, so those
records are indistinguishable to the classifier. Retaining them permits
identical records in both training and test partitions, inflating measured
performance. No duplicate group carries conflicting labels, so this is
redundancy rather than label noise. Deduplication in feature space yields
275,663 transactions and 473 fraud cases. A sensitivity analysis retaining
duplicates is reported in Ch.6.

## 3.2 Experimental Design
Stratified 70/15/15 split, seed 42, identical pipeline and tuning budget for
every technique (addresses Gap 3).

## 3.3 Feature Treatment
Time dropped (offset in seconds, not generalisable); Amount log1p-transformed
(right-skewed, max EUR 25,691, 1,825 zero-amount records); StandardScaler fitted
on training partition only.

## 3.4 Evaluation Metrics
Primary: AUC-PR. Also precision, recall, F1, MCC, G-mean, Brier, precision@k.
Accuracy excluded as a headline metric. Threshold selected on validation.
Bootstrap 95% CIs (stratified, 1000 replicates). Friedman + Nemenyi post-hoc.
